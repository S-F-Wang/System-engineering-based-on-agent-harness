# Require explicit Model Specs without a model catalog

OpenAICompatibleConfig will contain transport concerns, while a separate ModelSpec defines model identifier, optional context window, maximum output tokens, and Tool support. The Python API accepts ModelSpec explicitly and never infers capabilities from a model name. The CLI resolves its model identifier from environment or arguments and accepts context-window and output-token overrides; maximum output defaults conservatively to 4096. An unknown context window is allowed but disables threshold-triggered Compaction with a warning, while a normalized overflow may still trigger one recovery attempt. Missing Provider usage may be supplemented by a Token Estimate carrying `estimated=true`. Version one neither probes `/models` for unreliable metadata nor ships a fast-aging model catalog. Effective ModelSpec and usage provenance are retained in Run Trace, and the Session preserves the model identity and necessary specification for explainable continuation.
